================================================================
 VOKER · ПОЛНЫЙ АЛГОРИТМ BUG BOUNTY (веб)
 Методология «от нуля до отчёта». Не только Voker — весь стек.
================================================================

Главное правило: работай СТРОГО в рамках scope программы. Выход за scope —
бан в лучшем случае, уголовное дело в худшем. Читай правила программы ДО начала.
Что можно, что нельзя, разрешён ли автоматический скан, есть ли rate-limit.

Инструменты, помеченные [Voker], есть в тулките. Остальные — стандартный стек,
который стоит поставить отдельно.

----------------------------------------------------------------
ШАГ 4. РУЧНОЕ ТЕСТИРОВАНИЕ (ЯДРО BUG BOUNTY) — BURP SUITE
----------------------------------------------------------------
Проксируй трафик через Burp и проверяй по классам уязвимостей.
Учебник по каждой: PortSwigger Web Security Academy (бесплатно).

Частые классы багов и на что смотреть:
- IDOR / Broken Access Control: подмена id, доступ к чужим объектам,
  разница ролей. Самый прибыльный класс для новичка.
- XSS (reflected/stored/DOM): точки ввода → отражение в ответе.
  Инструмент: dalfox.
- SQL-инъекции: параметры в запросах. sqlmap для подтверждения. [Voker: sqlmap]
- SSRF: параметры с URL, «загрузи по ссылке», webhooks.
- Аутентификация: сброс пароля, JWT (алгоритм none, слабый секрет),
  2FA-обходы, race conditions.
- CSRF: важные POST без токена.
- File upload: обход фильтров, path traversal.
- Business logic: скидки, лимиты, повтор запроса, отрицательные значения.
- Открытые редиректы, subdomain takeover (dnstwist, проверка CNAME на
  «висящие» сервисы).

----------------------------------------------------------------
ШАГ 5. ПОДТВЕРЖДЕНИЕ И PoC
----------------------------------------------------------------
- Убедись, что баг воспроизводится стабильно.
- Оцени реальный impact (что реально может сделать злоумышленник).
- Сделай минимальный чёткий PoC: шаги + запрос/ответ + скриншот/видео.
- НЕ выходи за рамки: не читай чужие реальные данные больше необходимого,
  не удаляй, не ломай продакшн, не тестируй DoS (обычно запрещён).

----------------------------------------------------------------
ШАГ 6. ОТЧЁТ (ПОЛОВИНА УСПЕХА)
----------------------------------------------------------------
Хороший отчёт = быстрая выплата. Структура:
- Title: короткий и точный («IDOR в /api/orders раскрывает чужие заказы»).
- Severity / CVSS: обоснуй.
- Description: что за баг, где.
- Steps to Reproduce: по шагам, чтобы триажер повторил за минуту.
- Impact: что это даёт атакующему (бизнес-язык).
- PoC: запросы, скриншоты, видео.
- Remediation: как починить (плюс к репутации).
Voker собирает лог сессии в HTML (меню → o) — приложи как приложение к отчёту.
