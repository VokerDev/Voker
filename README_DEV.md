# Voker — заметки разработчика

Внутренний документ для тебя: как устроено, как расширять и как обновлять репозиторий.

## Главный принцип: оркестратор, а не сборник

Voker **не хранит инструменты внутри**. Он проверяет через `shutil.which()`, есть ли
бинарник; если нет — показывает команду установки; если да — собирает аргументы и
запускает через `subprocess.run()`. Плюс есть **встроенные функции** на чистом Python
(Base64, хеши) — они не требуют установки вообще.

Почему не «всё вшить»: это уже сделали Kali/Parrot/BlackArch, весит десятки гигабайт
и упирается в лицензии. Наша ценность — простой путь для новичка, а не набор бинарников.

## Что изменилось в v0.3

- **55 команд** в 6 категориях (добавлены DNS-инструменты, masscan, tcpdump→pcap,
  ffuf/dirb/nuclei/sqlmap, CTF-набор strings/binwalk/steghide, куча встроенных функций).
- **Сбор результатов.** Каждая команда пишется в `~/.voker/results/`:
  `*.txt` (полный вывод), `session_*.json` (сводка сессии), `*.pcap` (у tcpdump).
- **Сводная таблица** сессии печатается после каждой команды и по пункту `[r]`.
- Вывод внешних тулзов перехватывается построчно (`run_and_capture`) и одновременно
  показывается — кроме `interactive`-инструментов (wifite, steghide), они идут
  напрямую и не сохраняются.
- Без подтверждения перед запуском и без эха команды (как в v0.2).
- **Одноразовое** правовое предупреждение оставлено намеренно. Убрать — удали вызов
  `ensure_disclaimer()` в `main()`. Твой проект — решать тебе.

> Про принцип «есть в Kali → легально»: это миф. В Kali полно инструментов, применять
> которые к чужим целям незаконно. Легально не «то, что есть в Kali», а то, что ты
> запускаешь по своим системам или с письменного разрешения. Поэтому чисто
> разрушительные вещи (DoS и т.п.) в набор не входят.

## Как устроен сбор результатов

- `RESULTS_DIR = ~/.voker/results` — сюда всё пишется (репозиторий не засоряется).
- `SESSION` — список словарей текущего запуска; `save_result()` дописывает txt и
  переписывает `session_<SESSION_ID>.json`.
- `run_and_capture()` — стримит и собирает вывод; `interactive`-пункты идут через
  обычный `subprocess.run` без захвата.
- `{outfile}` в `args_template` + `outfile_ext="pcap"` — так tcpdump пишет файл,
  который потом помечается как артефакт в JSON.

## Что за что отвечает

| Блок                          | Отвечает за                                   |
|-------------------------------|-----------------------------------------------|
| `class C`, `col`              | ANSI-цвета, фиолетовая палитра                 |
| `panel_card/open/close`, `rail` | красивые панели вывода                       |
| `Action`, `Category`         | модель одного пункта и категории              |
| `fn_*`                        | встроенные функции (Base64, хеши)             |
| `TOOLKIT`                     | **реестр всех команд** — главное, что правишь  |
| `ensure_disclaimer`          | одноразовое правовое предупреждение           |
| `show_install_help`          | подсказка по установке под текущую систему     |
| `build_command`              | сборка аргументов (+ sudo при `needs_root`)    |
| `run_action`                 | объяснение → ввод → запуск → панель            |
| `main_menu`, `category_menu` | навигация; `show_installed` — пункт `[i]`      |
| `print_tree`                 | режим `--list`                                 |

## Как добавить внешний инструмент

Допиши один `Action` в нужную категорию `TOOLKIT`. Пример — `dnsrecon`:

```python
Action(
    name="Глубокая разведка DNS",
    desc="Расширенный сбор DNS-записей и зон.",
    explain="Собирает максимум информации из DNS домена: записи, зоны, поддомены.",
    prompt="Введи домен", binary="dnsrecon",
    install={"apt": "sudo apt install dnsrecon"},
    args_template="-d {target}",
    requires_auth=True,   # если активно обращается к цели
),
```

Поля: `binary` — что искать/запускать; `install` — `{менеджер: команда}`;
`args_template` — шаблон, `{target}` подставится из ввода; `prompt` — вопрос
(пусто = без ввода); `explain` — понятное объяснение; `requires_auth` — пометка
«активно обращается к цели»; `needs_root` — добавит `sudo`; `note` — подсказка.

## Как добавить встроенную функцию (без внешнего инструмента)

1. Напиши функцию, принимающую строку и возвращающую список строк:

```python
def fn_rot13(s: str):
    import codecs
    return [codecs.encode(s, "rot13")]
```

2. Добавь `Action` с `func=` вместо `binary`/`install`:

```python
Action(
    name="ROT13",
    desc="Простой шифр сдвига на 13.",
    explain="Сдвигает каждую букву на 13 позиций. Классика CTF-разминки.",
    prompt="Введи текст", func=fn_rot13,
),
```

## Как редактировать и обновлять репозиторий

После первой выгрузки цикл всегда одинаковый.

**1. Проверь, что изменилось:**
```bash
git status
```

**2. Добавь изменения и зафиксируй их (коммит):**
```bash
git add .
git commit -m "Понятное описание, что сделал"
```
Пиши осмысленно: «добавил ROT13 и категорию Крипто», а не «фикс».

**3. Отправь на GitHub:**
```bash
git push
```

**Полезное по мелочи:**
- Посмотреть историю: `git log --oneline`
- Отменить незакоммиченные правки в файле: `git checkout -- voker.py`
- Забрать изменения с GitHub (например, если правил через сайт):
  ```bash
  git pull
  ```
- Не хочешь тащить в репозиторий мусор (кэш Python и т.п.) — заведи `.gitignore`:
  ```bash
  printf "__pycache__/\n*.pyc\n.voker/\n" > .gitignore
  git add .gitignore && git commit -m "add gitignore" && git push
  ```

**Работа над крупной фичей, чтобы не сломать рабочую версию** — делай в отдельной ветке:
```bash
git checkout -b new-feature   # создать и перейти в ветку
# ...правишь, коммитишь...
git push -u origin new-feature
# когда готово — слить в main через Pull Request на сайте GitHub
```

## Идеи для развития

- Поддержка Windows (`where` вместо `which`, другие команды установки).
- Экспорт результата сканирования в файл/отчёт.
- Конфиг `~/.voker/config.toml` (пути к словарям, дефолтные флаги).
- Навигация стрелками через `textual`.
